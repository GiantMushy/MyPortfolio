How the site actually works (30-second version): the repo is a small web app. Every time you push, GitHub runs it, takes a "photo" of the rendered page, and publishes that snapshot as the static site. This is good news for the plan below — at publish time the app can look inside the image folders itself and lay out projects automatically, which is exactly what makes the "rename a file to reorder it" idea work with zero extra effort per update.

Recommended order

A. Quick fixes→ B. Image reorganisation→ C. Project cards→ D. Detail view redesign

A is independent and can ship immediately. B is the foundation — both C and D read the numbered image sets it creates, so it goes first. C and D are independent of each other and can be done in either order (or in parallel runs).

UI/UX decisions (answered 2026‑09‑19)

Defaults I'll use unless you say otherwise

  • Card arrows & detail carousel wrap around (last image → first).
  • Detail carousel is manual only — no auto-advance.
  • Detail carousel shows small position dots under the image so you know where you are.
  • The play badge on cards is always visible (it advertises "this one's playable"), and clicking it goes straight to itch.io in a new tab without opening the detail view.
  • The "Play here" link at the top of detail descriptions becomes a styled ▶ Play on itch.io button.
  • Phones/tablets have no hover: cards show the still frame, tapping opens the project. Card arrows and gif playback stay desktop-only; the detail carousel arrows work everywhere.
  • Projects with no images (Teaching, for now) simply skip the carousel and gallery.
  • The hero card shows the full new job title with the Klar Banking link. The tiny byline under "Thor" in the top bar gets a compact version (Junior Developer & Indie Game Dev) if the full line crowds the bar — say the word if you'd rather force the full text there too.
